# Evaluation runbook: running the RAG ablation on the frozen corpus

This runbook is for a collaborator who clones the fork and runs the RAG
ablation on their own machine. The runs use the frozen core corpus under the
of-record spec `grader_ablation_spec.json`. Everything here runs from the
**AgentiGrid project root** (`ExaGO/agentigrid/`).

Conditions (identical in the paper and the spec):

| Id | Retrieval | Grader |
|---|---|---|
| C0-norag | off | — |
| C1-basic | basic top-k | — |
| C2a-crag-cosine | corrective | cosine similarity |
| C2b-crag-reranker | corrective | local cross-encoder (`BAAI/bge-reranker-base`) |

C2c (the Platt-calibrated reranker) is offline only; see section 7.

---

## 1. Prerequisites

| Need | Check |
|---|---|
| This branch (`amir/agentigrid-rag`) checked out **inside the ExaGO repo**, so `../datafiles` resolves | `ls ../datafiles/case_ACTIVSg200.cont` |
| ExaGO built; `opflow`, `scopflow` and `pflow` reachable from `applications/` or `exago.binary_dir` | `ls applications/` |
| Python venv with AgentiGrid installed | `pip install -e . && pip install -r requirements.txt` |
| `chromadb` (the vector store; **not** in requirements.txt) | `pip install chromadb` |
| `sentence-transformers`, for C2b only | `pip install sentence-transformers` |
| Ollama with `nomic-embed-text` (embeddings for every retrieval condition) | `ollama list` |
| Ollama chat models listed in the spec (`llama3:latest`, `qwen2.5:7b`) | `ollama pull llama3 && ollama pull qwen2.5:7b` |
| `ANTHROPIC_API_KEY`, for the hosted model | `echo ${ANTHROPIC_API_KEY:+set}` |

Configuration:

```bash
cp configs/default_config.yaml.template configs/default_config.yaml
cp configs/env_setup.sh.template configs/env_setup.sh     # set LD_LIBRARY_PATH / PATH for ExaGO
mkdir -p data && cp ../datafiles/case39.m data/            # data/ is git-ignored; the spec reads ./data/case39.m
```

In `configs/default_config.yaml`, set `exago.binary_dir` if the binaries are not
in `./applications`. Keep `exago.mpi_np: 1`: with more than one rank AgentiGrid
switches SCOPFLOW to EMPAR, which does not solve the security-constrained
problem, and the evaluator rejects those runs as not N-1-secure.

## 2. Rebuild the vector store from the frozen corpus

`rag/corpus/` is versioned, and `rag/corpus/corpus_manifest.json` records its
SHA-256. The store (`rag/store/`) is **not** in git, so every machine builds its
own:

```bash
export OLLAMA_HOST=http://localhost:11434      # WSL with Ollama on Windows: see gotcha G1
python rag/tools/corpus_guard.py --spec grader_ablation_spec.json rag/corpus   # expect "0 finding(s)"
python -m agentigrid.rag.ingest rag/corpus
python -c "from agentigrid.rag.corpus_hash import corpus_status as s; print(s('rag/corpus','rag/store'))"
```

The last line must print `'ok': True`, and its `corpus_sha256` must equal the
one in `rag/corpus/corpus_manifest.json`. The runner performs the same check
before every retrieval condition and refuses to start if it fails.

**Do not edit, add or remove anything in `rag/corpus/`.** Any change produces a
different hash, so your runs would no longer use the corpus reported in the
paper. A new corpus version needs its own freeze (section 8).

Corpus v1 contents: ExaGO `--help` text, case metadata, AgentiGrid schema
exemplars, and 23 solver-certified worked exemplars from held-out tasks (case9mod,
case118 and ACTIVSg500; generated by claude-sonnet-5 under C0). None of these
come from an evaluated network or goal (ACTIVSg200, case39).

Quick retrieval smoke test, with no solver and no LLM:

```bash
AGENTIGRID_RAG_MODE=basic python -c "
import os; from agentigrid.rag import build_retriever
r = build_retriever(host=os.environ['OLLAMA_HOST'])
print(r.retrieve('Relieve all overloaded transmission lines without shedding load')[:1500])"
```

## 3. Dry run, then pilot

```bash
python rag/tools/experiment_runner.py --spec grader_ablation_spec.json --dry-run | tail -5
```

The dry run prints the matrix size and every command. A condition it cannot run
as labelled (for example C2b without `sentence-transformers`) is listed as
"not implemented", and the real run refuses to start until you fix it or pass
`--skip-unimplemented`.

Run a 1-rep pilot into its own folder before the full run:

```bash
python - <<'EOF'
import json; s = json.load(open("grader_ablation_spec.json"))
s["reps"] = 1; s["out_dir"] = "experiments/pilot_v1"
json.dump(s, open("pilot_spec.json", "w"), indent=2)
EOF
python -u rag/tools/experiment_runner.py --spec pilot_spec.json 2>&1 | tee pilot.log
```

---

## 4. Of-record run

```bash
python -u rag/tools/experiment_runner.py --spec grader_ablation_spec.json 2>&1 | tee ofrecord.log
```

- Runs are sequential; the runner pairs each run with the journal file it creates in `workdir/`.
- Each run writes `experiments/ofrecord_v2/<case>__<goal>__<condition>__<model>__r<N>/` containing `manifest.json`, `journal.json` and `run.log`.
- Re-running the same command resumes. Runs with `"status": "ok"` are skipped, and `failed` / `llm_error` runs are redone.

Monitor progress from a second terminal:

```bash
ls experiments/ofrecord_v2 | wc -l                                   # run folders so far
grep -l '"status": "ok"' experiments/ofrecord_v2/*/manifest.json | wc -l
tail -3 "$(ls -td experiments/ofrecord_v2/*/ | head -1)run.log"       # the current run
```

## 5. Evaluate

```bash
python rag/tools/experiment_eval.py --runs experiments/ofrecord_v2
```

This writes `analysis/per_run.csv`, with every column below for each run, and
`analysis/summary.csv`, with the mean and 95% CI per (case, goal, condition,
model) cell. The summary aggregates the rates, cost, token, time and H3 rate
columns. `guard_rejections`, `intent_<guard>` and `discarded_*` are in
`per_run.csv` only. The main columns:

| Column | Meaning |
|---|---|
| `valid_proposal_rate` | iterations after the baseline that applied a real modification ÷ `max_iter` |
| `cost_improvement_pct` | guarded: solves that violate a goal constraint do not count |
| `goal_attained` / `iterations_to_goal` | the goal's predicate (`target_pct`, `n1_secure`, `no_violations`) on a single solve |
| `baseline_attained` | 1 = iteration 0 already met the goal, so the cell measures nothing; fix the case before analysing it |
| `validator_rejection_rate` | H3: LLM iterations rejected by the parser or validator, in whole or in part |
| `intent_violation_rate`, `intent_<guard>` | H3: executed proposals that break a stated goal constraint (a lower bound: only the enumerated constraints are checked) |
| `guard_rejections` | solves that met the predicate but broke a guard |
| `discarded_truncated`, `discarded_api_error` | harness losses, excluded from the H3 rates |
| `llm_*` | token counts from every LLM call; derive USD offline at the rates in effect at execution |

## 6. Gotchas

| # | Symptom | Cause / fix |
|---|---|---|
| G1 | Ingest or retrieval fails with "connection refused" (WSL) | Ollama runs on Windows and WSL cannot reach it on `localhost`. In PowerShell: `$env:OLLAMA_HOST="0.0.0.0"; ollama serve`, and allow the firewall prompt. In WSL: `export OLLAMA_HOST=http://$(ip route show default \| awk '{print $3}'):11434`, then `curl -s $OLLAMA_HOST/api/version`. |
| G2 | Local-model runs fail although embeddings work | Embeddings read `OLLAMA_HOST`; the Ollama **chat** backend reads only `llm.ollama_host` from `configs/default_config.yaml`. Set both to the same address. |
| G3 | The runner refuses retrieval conditions ("corpus not frozen" / "store was built from a different corpus version") | Repeat section 2. `--allow-unfrozen-corpus` exists for pilots only; it is recorded in every manifest and such runs are not of-record. |
| G4 | Runs end as `llm_error` with zero tokens | The API key is missing in this shell; each new or split terminal needs `export ANTHROPIC_API_KEY=...`. Re-run the runner: `llm_error` runs are redone. |
| G5 | Nothing prints for minutes | Output is buffered when piped. Use `python -u` and monitor as in section 4. A run takes minutes (SCOPFLOW longest), and the spec timeout is 1800 s. |
| G6 | You want to redo runs | Move their folders out; do not delete them (they are data): `mkdir -p experiments/_retired/<label> && mv experiments/ofrecord_v2/<pattern> experiments/_retired/<label>/`. Use a new `<label>` each time, because `mv` refuses to overwrite a non-empty folder of the same name. |
| G7 | C2b runs start, but the grader is not calibrated | Without `AGENTIGRID_CRAG_TAU_LOWER` / `_UPPER` in the C2b `env`, corrective mode falls back to the **cosine** default thresholds (0.30 / 0.50) applied to reranker scores. Fit the thresholds first (section 7) and add both variables to the C2b condition. The first C2b run downloads the reranker model from Hugging Face; on an offline machine set `AGENTIGRID_RERANKER_MODEL` to a local copy. |
| G8 | SCOPFLOW never converges on a case AgentiGrid rewrote | This happens only with pre-fix code: before patch 0010 the writer emitted `}` instead of `};` for `mpc.genfuel`, and ExaGO then drops the fuel types (ramp rates 0). Use this branch; the frozen cases in `rag/tools/specs/cases/` were written after the fix. |
| G9 | Two runners at once mix up journals | Runs pair with journals by snapshotting `workdir/`. Never run two runners, or the GUI, on the same `workdir` at the same time. |
| G10 | Hosted-model parameters differ between models | Some models reject `temperature`; the backend retries without it and records `temperature_sent: false` in `llm_usage`. The output-token cap is fixed at 16000 for every condition (spec-level `env`) and recorded as `llm_usage.max_tokens`. |
| G11 | You are tempted to add ACTIVSg200 or case39 material to the corpus | Don't. That is a hold-out leak (worked answers to the evaluated tasks). `corpus_guard.py` refuses to freeze such a corpus. |
| G12 | `case39-opflow` fails with "file not found" | `data/` is git-ignored; copy `../datafiles/case39.m` into `data/` (section 1). |

## 7. Relevance labels (C2b thresholds and C2c offline metrics)

```bash
python rag/tools/relevance_labels.py sample --out labels/pairs.csv
# fill the "label" column: 1 = the chunk would help an agent pursue this goal, 0 = it would not
python rag/tools/relevance_labels.py fit --labels labels/pairs.csv --heldout-goals relieve,n1cost10
```

`fit` splits the pairs by goal. On the fitting goals it fixes the C2b
thresholds and writes the two env lines for the C2b condition into its JSON report
(`labels/fit_report.json`). On the
held-out goals it reports AUC (cosine, reranker, calibrated) and ECE (reranker,
calibrated). Those held-out numbers are the C2c result; there are no C2c agent
runs.

## 8. Changing the corpus (a new version, not an edit)

Build a second corpus in its own folder and store, and give it its own
conditions. Leave the v1 corpus untouched.

```bash
python rag/tools/corpus_guard.py --spec grader_ablation_spec.json rag/corpus_docs --freeze
python -m agentigrid.rag.ingest rag/corpus_docs --store rag/store_docs
```

In the spec, the new conditions set `"corpus": "rag/corpus_docs"` and
`AGENTIGRID_RAG_STORE=rag/store_docs` in their `env`.
